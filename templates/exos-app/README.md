# ExOS application starter

A minimal application that runs on the ExOS **host "virtual board"** -- the whole
OS compiled as an ordinary process, no microcontroller required. Use it to
develop and debug ExOS apps and services on your Mac or Linux box with Xcode,
VS Code, or just a terminal, then build the same source for real hardware.

ExOS is consumed as a **source dependency** (a git submodule), so your app and a
known-good ExOS revision are versioned together.

## Layout

```
.
├── CMakeLists.txt      # add_subdirectory(exos) + exos_add_app(my_app ...)
├── CMakePresets.json   # host-ninja (terminal / VS Code) and host-xcode presets
├── Makefile            # thin CLI wrapper around CMake (optional)
├── app/
│   └── main.c          # your code -- an ordinary int main()
├── exos/               # the ExOS submodule (you add this -- see Setup)
└── .vscode/            # VS Code build/debug/IntelliSense config
```

## Prerequisites

- CMake **3.21+**
- A C compiler (clang or gcc) -- stock Apple clang is fine
- Ninja (recommended) and/or GNU Make
- git

## Setup

Add ExOS as a submodule named `exos` (the CMakeLists expects that path):

```sh
git submodule add <exos-repo-url> exos
git submodule update --init --recursive
```

(If you cloned a repo that already references the submodule, just run the second
command.)

## Build & run

### Terminal

```sh
cmake --preset host-ninja          # configure (Ninja, Debug, compile_commands.json)
cmake --build --preset host-ninja  # build
./build/my_app                     # run
```

(`cmake -S . -B build && cmake --build build` works too if you prefer no presets.)

Or via the convenience Makefile:

```sh
make run                 # configure + build + run
make clean
```

### Xcode (macOS)

Generate an Xcode project from the same CMakeLists and open it:

```sh
cmake --preset host-xcode
open build-xcode/my_exos_app.xcodeproj
```

Pick the **my_app** scheme and press ⌘R to build and run, or ⌘Y to debug. The
console output appears in Xcode's output pane. Only your executables get
schemes; ExOS's internal object libraries are hidden.

### VS Code (cross-platform)

Open this folder; VS Code offers the recommended extensions (**CMake Tools**,
**C/C++**, **CodeLLDB**). CMake Tools picks the `host-ninja` preset and
configures on open (see `.vscode/settings.json`).

- Build: `⇧⌘B` / `Ctrl+Shift+B` (the **cmake: build** task)
- Run/Debug: `F5` -- **Debug my_app (lldb)** uses CodeLLDB, **Debug my_app
  (cppdbg)** uses the Microsoft debugger (gdb on Linux)

IntelliSense is driven by `build/compile_commands.json`, generated by the
preset. The kernel runs all its threads on one OS thread, so the debugger shows
a single thread; stepping into kernel sources works as for any C code.

## Writing your app

`app/main.c` is a normal Unix-style program. ExOS boots the kernel first and
then runs your `main()` as the kernel's initial thread, so you can use POSIX
threads, mutexes, `printf`, `nanosleep`, etc. out of the box. `printf` and
friends go to `/dev/console`, which the virtual board wires to stdout.

To add more source files, list them in `exos_add_app(my_app SOURCES ...)`.

### Adding a background service

Register work to run at kernel init with `EXOS_INITIALIZER` (see ExOS's
`examples/hello_service` for a complete example):

```c
#include <kernel/thread.h>
#include <support/services/init.h>

static void _start(void) { /* spawn a worker thread, etc. */ }
EXOS_INITIALIZER(_my_service, EXOS_INIT_SERVICE, _start);
```

## Real hardware

This template targets the host virtual board. The ARM firmware build lives in
ExOS's SEGGER Embedded Studio project files and is independent of this CMake
setup; the same `app/main.c` is intended to build for both.
